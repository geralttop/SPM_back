# 🛡️ Руководство по Rate Limiting и Brute-Force защите

## 📊 Лимиты запросов

### Глобальные ограничения
Применяются ко всем endpoints по умолчанию:
- **3 запроса в секунду**
- **20 запросов за 10 секунд**
- **100 запросов в минуту**

### Специальные ограничения

#### 🔐 Аутентификация (строгие лимиты)
| Endpoint | Лимит | Период | Причина |
|----------|-------|--------|---------|
| `/auth/register` | 5 | 1 минута | Предотвращение спама регистраций |
| `/auth/login` | 5 | 1 минута | Защита от brute-force паролей |
| `/auth/verify-email` | 3 | 1 минута | ⚠️ Критично: защита кодов |
| `/auth/verify-login` | 3 | 1 минута | ⚠️ Критично: защита кодов |

#### 🔧 Управление аккаунтом
| Endpoint | Лимит | Период | Причина |
|----------|-------|--------|---------|
| `/auth/delete-me` | 2 | 5 минут | Предотвращение случайного удаления |
| `/auth/refresh` | 10 | 1 минута | Нормальное обновление токенов |
| `/auth/update-profile` | 5 | 1 минута | Предотвращение спама изменений |

#### 👑 Административные
| Endpoint | Лимит | Период | Причина |
|----------|-------|--------|---------|
| `/auth/user/:id` | 10 | 1 минута | Массовые операции админа |

#### ✅ Исключения
- `/auth/profile` - без ограничений (только JWT проверка)

## 🚫 Brute-Force защита

### Защита кодов подтверждения
- **Максимум**: 3 неверных попытки
- **Блокировка**: 15 минут
- **Применяется к**: verify-email, verify-login

### Защита паролей
- **Максимум**: 5 неверных попыток
- **Блокировка**: 30 минут
- **Применяется к**: login

## 📱 Обработка ошибок

### Rate Limiting (429)
```json
{
  "statusCode": 429,
  "message": "ThrottlerException: Too Many Requests"
}
```

**Рекомендации клиенту:**
- Подождать и повторить запрос
- Реализовать exponential backoff
- Показать пользователю сообщение о временном ограничении

### Brute-Force блокировка (400)
```json
{
  "message": "Слишком много неверных попыток. Повторите через 15 минут.",
  "error": "Bad Request",
  "statusCode": 400
}
```

**Рекомендации клиенту:**
- Показать точное время блокировки
- Предложить восстановление пароля
- Заблокировать UI на время блокировки

## 🔧 Настройка для разработки

### Временное отключение
Для тестирования можно временно отключить:

```typescript
// В app.module.ts - закомментировать
// {
//   provide: APP_GUARD,
//   useClass: ThrottlerGuard,
// },

// В auth.controller.ts - добавить
@SkipThrottle()
@Post('endpoint')
```

### Изменение лимитов
```typescript
// Глобальные лимиты в app.module.ts
ThrottlerModule.forRoot([
  {
    name: 'short',
    ttl: 1000,    // время в мс
    limit: 3,     // количество запросов
  }
])

// Специальные лимиты в контроллере
@Throttle({ default: { limit: 10, ttl: 60000 } })
```

## 📈 Мониторинг

### Логи для отслеживания
```bash
# Поиск rate limiting
grep "ThrottlerException" logs/

# Поиск brute-force атак
grep "заблокирован" logs/
grep "Неверный код" logs/
grep "Неверный пароль" logs/

# Поиск подозрительной активности
grep "Попытка.*заблокированным" logs/
```

### Метрики для мониторинга
- Количество 429 ошибок в минуту
- Количество заблокированных пользователей
- Топ IP адресов по количеству запросов
- Время блокировки пользователей

## 🚀 Продакшен

### Рекомендации
1. **Настройте reverse proxy** (nginx) с дополнительным rate limiting
2. **Используйте Redis** для хранения счетчиков (масштабируемость)
3. **Настройте алерты** на превышение лимитов
4. **Логируйте IP адреса** для анализа атак
5. **Рассмотрите CAPTCHA** после нескольких блокировок

### Конфигурация Redis
```typescript
ThrottlerModule.forRoot({
  storage: new ThrottlerStorageRedisService(redisClient),
  // ... остальные настройки
})
```
